# AGENTS.md — Agent Guide

Guidance for AI agents and human developers working on this repository.

## Project Overview

A production-ready OpenVPN management panel replicating OpenVPN Access Server
features, built on open source components:

- **Backend**: Java 25, Spring Boot 3.5, Gradle (Kotlin DSL), JPA + Hibernate, SQLite (WAL) with a portable-to-PostgreSQL path
- **Frontend**: React 18 + TypeScript, Vite, MUI v6 (Material), TanStack Query, React Hook Form + Zod
- **VPN core**: OpenVPN Community Edition 2.7 + Easy-RSA 3.1 + OpenVPN Management Interface
- **Deploy**: Docker Compose, Makefile, `install.sh`

**Language rule**: ALL code identifiers, comments, commit messages, UI strings, and
docs are in **English**.

## Commands

All typical operations go through the Makefile. Always run from repo root.

```bash
make up          # build + start all services
make down        # stop services
make build       # build backend (gradle) + frontend (npm) + images
make logs        # tail all container logs
make test        # backend + frontend tests
make backend-dev # run backend locally (needs env)
make frontend-dev# run frontend with Vite dev server
make migrate     # apply flyway migrations
make seed-admin  # create initial admin user (non-wizard)
make backup      # produce backup archive
make api-docs    # start swagger-ui hint
```

### Backend (Gradle)

```bash
cd backend
./gradlew build        # compile + test + assemble
./gradlew bootRun      # run locally
./gradlew test         # unit + integration tests
./gradlew spotlessApply
```

Backend runs on port `8080`. Expects env vars from `.env` (see `.env.example`).

### Frontend (npm)

```bash
cd frontend
npm install
npm run dev        # Vite dev server (port 5173, proxies /api + /ws)
npm run build
npm run lint
npm run test
```

## Conventions

### Backend

- Package root: `com.opnl.vpn`. Subpackages: `config`, `security`, `auth`, `user`,
  `pki`, `profile`, `access`, `network`, `ccd`, `monitor`, `node`, `audit`,
  `backup`, `api`, `internal`, `common`.
- Entities in JPA; prefer JPQL/Criteria over native SQL so PostgreSQL migration stays trivial.
- SQLite-specific SQL is forbidden in repositories; use portable JPQL only.
- Settings (per-user/group/server) stored as JSON strings in TEXT columns via a
  Jackson `JsonNode`/Map attribute converter — never as SQLite `JSON` type.
- Error handling: `ApiException` (common) with `ApiError` DTO → `@RestControllerAdvice`.
- Validation via `jakarta.validation` annotations on DTOs.
- Service layer is transactional and thin; controllers only map HTTP ↔ service.
- Expose only DTOs in `api` package; never leak entities.
- All REST endpoints under `/api/**` (admin) and `/api/portal/**` (self-service).
  Script-facing endpoints under `/internal/**` (network-restricted).
- Every controller/service method that mutates state is covered by a unit test.
- API docs via springdoc (`/swagger-ui.html`, `/v3/api-docs`): `config/OpenApiConfig`
  defines the global `bearerAuth` HTTP/Bearer-JWT security scheme + security requirement
  so Swagger UI shows an "Authorize" button for testing (token from `/api/auth/login` or
  `/api/auth/mfa`). Keep it in sync with the auth model; new controllers should carry
  `@Tag`/`@Operation` summaries.

### Frontend

- Feature-folder structure under `frontend/src/features/<feature>/`.
- MUI v6; theme with dark mode **default** (light available). Access Server–style.
- Server state via TanStack Query (`@tanstack/react-query`); forms via React Hook Form + Zod.
- Tables for user/list views use `@mui/x-data-grid`.
- Toast notifications via a small wrapper around MUI Snackbar; confirmations via MUI Dialog.
- All user-facing strings English.

### OpenVPN integration

- Server configs generated by the backend into the shared config volume;
  openvpn container mounts them read-only.
- Scripts under `openvpn/scripts/` call back into the backend via `http://backend:8080/internal/**`
  (restricted network). Their contract must stay compatible with `InternalAuthController`.
- Management interface: backend opens a persistent TCP client to `openvpn:7505`.
  Protocol: plain text lines; async events start with `>`. See `docs/architecture.md`.

### Security

- Never commit secrets. All secrets via `.env` (see `.env.example`) or runtime injection.
- Passwords hashed (Argon2id preferred); TOTP via `dev.samstevens.totp`.
- JWT: short-lived access + rotating refresh token; RBAC via `ADMIN`/`GROUP_ADMIN`/`USER`.
- Endpoints that write data require admin role unless explicitly `@Anonymous`/portal-scoped.
- The openvpn container requires `NET_ADMIN` for iptables-based access control — document, don't ignore.

### Testing

- Backend: JUnit 5 + Mockito. Integration tests with Spring Boot test slices; DB tests
  against a temp SQLite file. Keep tests hermetic (no docker required).
- Frontend: Vitest + React Testing Library for components/hooks.
- Before finishing a task run: `make test`.

### Git

- Follow existing commit message style (imperative, English, concise).
- Only commit when explicitly asked.
- Release tagging convention: whenever `RELEASE_NOTES.md` is updated for a
  released milestone, give the milestone a SemVer version (e.g. `v0.1.0-alpha.1`),
  set it as the release-notes heading, and record it as an annotated git tag
  pushed to `origin` (`git tag -a <version> -m "<version>" && git push origin <version>`).

## Environment Variables

Full reference in `docs/configuration.md`; template in `.env.example`. Key ones:

| Variable | Purpose |
|---|---|
| `OPNL_DB_URL` / `OPNL_DB_USER` / `OPNL_DB_PASSWORD` | JDBC connection (SQLite file URL by default) |
| `OPNL_JWT_SECRET` | JWT signing secret (min 32 bytes) |
| `OPNL_OPENVPN_MGMT_HOST` / `OPNL_OPENVPN_MGMT_PORT` | Management interface endpoint |
| `OPNL_OPENVPN_MGMT_PASSWORD` | Management interface password (mandatory; backend refuses to start without it) |
| `OPNL_INTERNAL_TOKEN` | Shared token guarding `/internal/**` (mandatory; placeholder rejected) |
| `OPNL_OPENVPN_ADMIN_HOST` | VPN server admin hostname/IP (pushed to clients) |
| `OPNL_DATA_DIR` | shared volume: PKI, CCD, configs, db |
| `OPNL_BRAND_NAME` | default product name |
| `OPNL_ADMIN_PASSWORD` | bootstrap admin password (wizard/seed) |

## Definition of Done

1. Feature implemented behind a clean service + DTO boundary.
2. Unit tests for new logic (backend + frontend where applicable).
3. `make test` green.
4. TODO.md checkbox updated.
